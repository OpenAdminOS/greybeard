# Lessons

- 2026-07-04: Status markers (OK/WARN/FAIL/PASS) assert the outcome of a check or action. Never attach them to rows that merely state facts (disclosures, scope lists, metadata); those get marker-free aligned info lines. Caught by the user after I presented the setup disclosure with OK on every informational row as finished work. Rule for review: before accepting CLI/UI output, read each line and ask what claim the marker makes; if nothing was checked or performed, the marker lies.
- 2026-07-05: Green local `npm run ci` does not equal green GitHub Actions CI. The root `ci` script runs build/test/style but NOT `npm ci`, so lock-file drift and cross-platform bugs stay hidden locally. First public CI run failed five different ways, fixed in sequence: (1) `package-lock.json` out of sync (dev on npm 11 / Node 25, CI on npm 10 / Node 20) - regenerate the lock with the SAME npm CI uses, and pin CI to a stable Node patch that ships that npm; (2) npm optional-deps bug (npm/cli#4828) dropped per-platform native binaries from an npm-10-regenerated lock - regenerate with npm 11 which records all platforms, and align CI to npm 11; (3) vitest 4 pulls a rolldown NATIVE binding that trips npm ci cross-platform - pin vitest to ^3 which has no native binding; (4) Linux runner lacks `libsecret-1.so.0` that `@azure/msal-node-extensions` dlopens at import - `apt-get install libsecret-1-0` in CI; (5) Windows path separators (backslash) in generated MCP config args + CRLF line endings breaking frontmatter parse - normalize `.js` script args to forward slashes (keep node exe native for schtasks), add `.gitattributes eol=lf`, make parsers CRLF-tolerant. Rule: never commit `"latest"` dependency ranges (they were the drift source); pin every dep. When fixing CI, read the actual `gh run view --log-failed`, fix one layer, push, watch - do not batch-guess.
